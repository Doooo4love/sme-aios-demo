# 批发与物流试点自动化

[English](pilot-automation.md)

## 哪些人工工作可以移交给系统

| 人工任务 | 当前自动处理 | 需要业务决策或试点证据 |
|---|---|---|
| 录入结构化采购单 | 检查字段、匹配买方 SKU、换算箱件、精确核算金额、生成草稿预览 | 确认伙伴数据映射、运费、折扣、税和舍入规则 |
| 重复录入同一订单 | 同仓库、相同规范化内容复用收件。同提交账号复用批量提案 | 确认客户的外部 PO 编号、跨渠道和跨账号去重、修订和撤单策略 |
| 检查扫描订单 | 支持模板用本地 OCR 和字段证据。演示工作台可用视觉模型检查争议裁剪 | 提供测试版式，复核缺失定位、模型冲突和歧义笔迹。测误通过率 |
| 放行常规草稿 | 独立主管可在一次请求内审批最多 50 个已审阅的提案摘要 | 确认授权、抽检政策、金额上限与二次复核规则 |
| 查运单或改交期 | 按范围查询。改期预览绑定 ERP 当前版本 | 确认 WMS 和承运商截单时间、假期、时区、运力、拆单及通知义务 |
| 确认 ERP 有没有写入 | 审计、操作 ID、有限读回。主管按仓库查看未完成核对和回执不符 | 验证桥接事务与恢复能力。人工判断明确拒绝、手工修改和无法对账的单 |

这些控制面向重复录入、算术校验、逐张审批和常规对账。节省多少人手，需要影子运行并记录现有人工处理时间。

## 结构化来单接口

`POST /v1/intakes/{warehouse}/structured/batch` 一次最多 50 单，整个请求体最大 64 KiB。CSV、EDI 或合作伙伴导出数据先映射到统一 JSON。示例如下。

```json
{"orders":[{"po":"B-100","buyer":"HBR-47","currency":"HKD","delivery":"2027-02-01","total":"50.00","lines":[{"sku":"TEA-24","unit":"CASE","quantity":2,"unit_price":"25.00","amount":"50.00"}]}]}
```

- 每个从零开始的 `position` 对应一个结果。 `status=prepared` 含 `intake_id`、`proposal_id`、`digest` 和当前 `state`。这一阶段没有 ERP 写入和 LLM 调用。重放可能返回原提案已审批或已核对的状态。
- `status=review` 含原因码。`INVALID_ORDER` 另有最多十条字段路径与校验代码。调用方在上游保留原件，按位置修正无法解析的行。符合结构但有业务问题的订单保存为收件，修正原始数据后重交。若只修正主数据，可重新提交原内容。
- 原因包括物料映射缺失、币种不支持、超限、金额异常、同批出现冲突修订和策略未通过。相同内容复用收件，同一提交者复用提案。跨批的同号异内容依赖客户修订策略和 ERP 外部单号唯一约束，沙盒在写入时检查唯一性。
- 业务错误只影响对应项目。数据库故障会回滚批次，可在恢复后重试。若提案过期且需重新提交，通过 `POST /v1/actions` 生成新预览并重新获批。自动重放批次会保留原提案。

`POST /v1/proposals/approve-batch` 接收 `{"proposals":[{"proposal_id":"…","digest":"…"}]}`。调用方先核对各预览。每项审批分别校验仓库权限、独立审批、可选 OPA 和摘要，返回每项 202、403、404 或 409。每项独立提交，断线后可重试相同列表。202 代表进入队列或此前已接收，最终状态需另查。

## 异常核对

主管或管理员调用 `GET /v1/operations/exceptions?limit=50`。将 `next` 对象原样作为下一页查询参数，直到它返回 null。视图显示已授权仓库的 `OUTCOME_UNKNOWN` 与 `NEEDS_OPERATOR`，随处理进展更新，并附最新相关事件。

| 事件或故障 | 处理 |
|---|---|
| 写入结果未知或派发租约已中断 | Worker 只读回执，避免第二次写 |
| `READBACK_LIMIT_REACHED` | 核对 ERP 服务与操作 ID，主管可重新发起只读核对 |
| `ERP_RECEIPT_MISMATCH` | 调查桥接服务，验证租户、ID、摘要和目标后再核对 |
| `INVALID_STORED_PLAN` 或 `PLAN_DIGEST_OR_TENANT_MISMATCH` | 必要时停写，保留审计，排查数据或配置 |
| 审批过期、撤权、运单版本变化、ERP 明确拒绝 | 查看提案时间线，需修正时生成新的授权预览 |
| 未建立规则的业务流程 | 保留原始资料，按客户批准的流程移交负责人 |

有 outbox 仍需要 ERP 写入与回执合同。UBL 等电子订单标准可以表达额外费用、折让、交付条件、改单和撤单。把伙伴数据映射到当前较窄的采购单合同前，需确认实际使用的格式和字段。[OASIS UBL 2.3](https://docs.oasis-open.org/ubl/os-UBL-2.3/UBL-2.3.pdf) · [事务 outbox](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)

## 合成性能测试与客户验收

安装 `requirements-test.txt` 后运行 `python scripts/platform_benchmark.py`。逐单和批量各运行三次，每轮 250 份唯一的合成单行订单。通过进程内 API 连接临时 SQLite 库，并确认全部 250 张 ERP 沙盒回执。批大小为 50。

| 开发环境中位数 | 逐单 | 批量 |
|---|---:|---:|
| 截止审批的 API 请求 | 750 | 10 |
| 录入、准备、审批 | 1.540 秒 | 0.169 秒 |
| Worker 派发与回执核对 | 0.444 秒 | 0.510 秒 |

测试不计客户端网络、真实 IdP 和 OPA、LLM、PostgreSQL 和远程 ERP。提速发生在录入和审批阶段，Worker 仍逐笔派发和读回。

首客需提供脱敏样本及人工确认结果、买方 SKU／包装资料、ERP 沙盒读写角色和业务量。按关键字段准确率、误通过率、无需重复录入比例、每单人工分钟、重复写入率、积压时长、P95 和每张核对成功单的成本验收。OCR 或外部模型评估为部分伙伴和版式保留独立测试集。使用团队现有人工操作数据作比较。[生产验收](production-readiness.md)
